首先一些会用到的软件就不提了，提前U盘里准备好安装包就行：
就是预留要用的各种软件的安装包以及一些工具（强烈建议备着VMWare的安装包，这东西相对比较难搞到）
接下来就是安装wsl，需要管理员shell
```bash
wsl --install   #执行完后重启
wsl --install --online  #查看已有发行版，这里用kali
wsl --install kali-linux  
#这是一个最小化安装，进入更新完后建议apt install kali-linux-large
```
wsl默认是nat模式，没法办法接收到反弹shell，这很不方便，需要改成mirror模式
在`C:\Users\<用户名>`目录下创建或者修改`.wslconfig`文件，内容如下：
```ini
[wsl2]
networkingMode=mirrored   # 关键一行

[experimental]
autoProxy=true          # 自动继承Windows代理设置
dnsTunneling=true       # DNS请求通过Windows解析
firewall=true           # 启用防火墙
```
随后`wsl --shutdown`，重启wsl生效
一开始我是在windows上运行opencode，但是兼容性极差，所以改在wsl中运行服务器，windwos只做连接
:::caution
如果是nat模式，宿主机里连接服务器的地址填wsl地址，但不要这么做。（外界无法连接到wsl，除非配置端口转发）
```powershell
#需要管理员
netsh interface portproxy add v4tov4 listenport=8080 listenaddress=0.0.0.0 connectport=8080 connectaddress=$(wsl hostname -I | awk '{print $1}')
#添加
netsh interface portproxy delete v4tov4 listenport=8080 listenaddress=0.0.0.0
#删除
```
opencode服务器地址写localhost:<opencode端口>。（nat模式下wsl可以通过localhost，访问到宿主机服务，但是反之只能通过IP）
:::
每次都要手动在wsl启动opencode相当麻烦，写个服务。
从安装开始(wsl请以root身份登录，`wsl -u root`)
```bash
curl -fsSL https://opencode.ai/install | bash
#官方安装脚本，安装后需要退出重进wsl或执行source ~/.bashrc
vi /etc/systemd/system/opencode.service
#创建service
```
写入
```ini
[Unit]
Description=OpenCode Server
After=network.target
[Service]
Type=simple
User=root
WorkingDirectory=/mnt/c/Users/<用户名>  
#这个其实关系不大，实际agent目录还是在连接到opencode后配置的
ExecStart=/root/.opencode/bin/opencode serve --hostname 0.0.0.0 --port 4096
#写opencode的实际路径，不知道就which opencode
#上面的安装脚本添加的环境变量只在当前用户，需要注意
Restart=always
RestartSec=3
[Install]
WantedBy=multi-user.target
```
执行
```bash
systemctl daemon-reload
systemctl enable --now opencode.service
#看日志journalctl -u opencode.service -f
```
随后宿主机opencode连接localhost:4096即可
::tip
镜像下，opencode会错误的将其认为是windows系统，因此工作目录选择走的是windows文件管理器，没有办法正常选择路径，这会使得无法在软件内看到文件目录，但不影响使用
opencode还提供web页面（和客户端其实是一样的）可以作为替代品避免路径没法正常使用的问题
```bash
opencode web --hostname localhost
#输出访问地址，端口随机
``` 
wsl和VM的虚拟网络**不能互通**，在不转发的情况下，mirrored/bridge的wsl无法访问到VM(nat情况下反之)，所以对于复现时用VM搭建的非桥接环境，不能使用这个wsl！（wsl的mirror只复制物理网卡）
::
其实这么说来最推荐的做法还是使用vm而不是wsl。
vm网络配置更为灵活，方便集成到windows(加个仅主机的网卡)，只是不能无缝访问宿主机文件）
